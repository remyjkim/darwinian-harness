00

Orientation

The authentication system is already correct; the missing product is an authorized Deployed Worker management client.

Situation

drwn already authenticates humans through DAH

The published CLI owns device flow, PKCE, services-audience access and refresh tokens, credential V3, keychain custody, refresh/revoke/logout and headless DRWN_TOKEN. Those mechanisms remain the sole client authentication authority.

Complication

Cloud commands still depend on a removed authorization model

List, status, deploy, rollback, secrets, chat and related commands address /api/minds by slug. I330/I321 replace deployer snapshots with live DAH Worker authority; a services bearer alone is intentionally insufficient.

Question

How can one CLI survive the hard cut without receiving confidential authority?

The client must gain organization context, stable Deployed Worker selectors, strict wire contracts and idempotent recovery while preserving its existing credential family and never seeing a dah-management token.

Answer

Extend auth readiness; add a private management kernel

The existing services bearer carries explicit delegated-management consent. A new internal route-keyed client sends it to the Services broker, which privately obtains request-local management authority and returns only sanitized typed results.

Primary invariant

The Worker CLI never owns management authority

It stores only the existing public-client credential family. Organization selection and project binding are non-secret hints. Every Worker-bound decision is performed by current DAH authority through Services-owned server contracts.

06

Worker components and local state

One private kernel separates cloud management from command parsing and from settled local project authority.

Existing authority · retained

cli/core/auth/

Device flow, PKCE, credential V3, resolve/refresh/revoke, auth receipts and scoped OS-keychain envelope. New code adds claim readiness; it does not add a token family.

New private component

cli/core/management/

Cloud profile, pinned route contracts, strict transport, selectors, context store, operation journal, error classifier and public command-result projection.

Thin commands

cli/commands/org/ + worker/

Parse intent, call one typed management operation and render its result. Commands do not build URLs, refresh tokens, inspect raw bodies or infer IDs.

Removed components

ACP · routines · runtime admission · BGDB Mind

No stubs except the provider-neutral worker mind parent. Removed code leaves no release member, dependency, state reader or documentation claim.

Strict cloud profile

interface DrwnCloudProfileV1 {
  schema: "drwn.cloud-profile";
  schemaVersion: 1;
  profileId: string;
  apiOrigin: string;
  webOrigin: string;
  authHubOrigin: string;
  issuer: string;
  resource: string;
  clientId: "drwn-cli";

}

Production and staging are complete reviewed tuples. Controlled local tests may load one strict profile file. Independent endpoint overrides cannot create a mixed issuer/resource/API profile.

Machine context

~/.agents/drwn/cloud-context.json

drwn.cloud-context V1, keyed by profile digest. Stores selected organizationId only.

Project target

.agents/drwn/cloud.local.json

drwn.project-cloud-context V1. Gitignored, mode 0600. Stores profile, organization and deployedWorkerId.

Pending operation

.agents/drwn/.cloud-operations/<id>.json

drwn.client-operation V1. Request fingerprint and non-secret progress; removed after verified receipt + context commit.

Isolation rule

Cloud state never enters committed project Worker selection, machine Worker intent, generated projections, credentials or future Mind provider configuration.

07

Existing authentication, extended consent

The client change is a consent and claim-readiness check—not a new authentication system.

1Login

One visible device ceremony

drwn login requests services access plus dah:management.delegate. The Auth Hub page displays elevated consent and records a live revocable grant.

2Persist

Credential V3 stays exact

The same access/refresh payload is encrypted through envelope V2. Scope remains a signed token claim rather than a new stored field.

3Preflight

Delegation readiness

Before management, verify exact issuer, audience, azp=drwn-cli, human subject, expiry and required scope family.

4Operate

Send only services bearer

The server privately obtains fresh management authority. The CLI has no management-token parser, field, log or recovery path.

Old credential

Readable for whoami and logout. A management command refuses before refresh and requires a fresh interactive login; refresh cannot silently acquire consent.

Headless credential

DRWN_TOKEN must carry the same issuer/audience/client/scope claims. It is never persisted or refreshed.

Stored credential 401

Refresh once, preserve the exact request bytes and request ID, validate retained scope, persist the next generation, then replay.

Credential backend

Linux Secret Service, macOS Keychain and Windows DPAPI are all blocking support targets. A packaged test-file backend is removed.

10

Registration and crash recovery

One command composes external authorities without creating a client-side workflow authority.

1Persist intent

Operation ID before network

Validate profile/org/name/environment; serialize canonical request; persist UUIDv4 + fingerprint under the project owner lock.

2DAH

Create/resolve Worker + intent

The stateless broker uses the same operation identity. Auth Hub remains organization and Worker writer.

3Foundry

Create/resolve aggregate + attach

Deploy-api writes D1, consumes the opaque intent through its confidential caller and persists complete binding projection.

4Readback

Validate distinct IDs and revisions

Receipt must carry organization, Worker, Deployed Worker and authoritative attachment facts—never Mind or credential fields.

5Commit context

Binding only after proof

Atomically write project target, then remove journal. Lost response/process restart resumes the same bytes and ID.

type RegistrationReceiptV1 = {
  schema: "cl.drwn.worker-registration.v1";

Reuse of an operation ID with different bytes fails. The CLI never synthesizes a replacement Worker/Deployed Worker, infers an ID from name or stores server phase internals.

16

External contract obligations

These are not Worker design choices; they must be frozen before G2 where they affect client-visible bytes.

Services contract artifact

Versioned language-neutral schemas, route key → method/template/capability, ID grammar, response/error vectors, secret negatives, manifest digest and source commit.

Organization authority union

Organization discovery cannot be forced into WorkerCapabilityV1; delegation classification must distinguish organization and Worker-bound authority.

DAH reverse binding authorization

Detail/mutation must authorize by deployedWorkerId and reveal workerId only on allow, avoiding D1-first existence lookup.

Direct deploy-api ingress

The legacy public origin must close or independently prove private broker provenance; caller-supplied management headers cannot bypass edge stripping.

Strict run route family

Start/status must stay Worker-bound and define polling/streaming bytes without placing ACP or raw server events in the CLI public contract.

Hard-cut minimum version

I336 config and 410/426 fixtures pin 1.4.2 from the exact release receipt; no package semver inference at runtime.
