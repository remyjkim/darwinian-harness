02

Decision gaps to close in Task 00

Every unresolved gap is stated in SCQA form, with a recommended answer and an explicit stop.

GAP-01 · Protocol bytes

One artifact, not parallel contract copies

Situation
The G1 freezes route-keyed management and strict parsing.
Complication
No immutable artifact currently exists.
Question
How do Worker and Services prove identical public bytes?

Recommended answer: Services publishes one closed JSON artifact. Worker vendors it at registry/contracts/deployed-worker.v1/contract.json, pins source commit and SHA-256 in cli/generated/drwn-management-contract-lock.json, and compiles its JSON Schemas with Zod. Block Tasks 03+ until digest conformance is green.

GAP-02 · Profile selection

Whole tuples only

Situation
Current API, web, Auth Hub and resource origins are independently overridable.
Complication
Mixed profiles can combine the wrong issuer, audience and public API.
Question
What is the exact selector and precedence?

Recommended answer: default to bundled production; allow bundled staging through DRWN_CLOUD_PROFILE; allow one absolute strict file only when selector is local. No endpoint overrides. Derive a canonical tuple digest for state isolation. Services must supply exact staging tuple bytes.

GAP-03 · Consent claims

Readiness, not local signature authority

Situation
Current JWT code decodes and checks issuer/audience/expiry; the server verifies signatures.
Complication
“Verify claims” could be misread as adding JWKS verification and a second auth component.
Question
Which public claims are required and where is cryptography enforced?

Recommended answer: freeze one scope claim shape, azp=drwn-cli, non-empty human subject, exact issuer/audience and expiry. Worker performs readiness assertions only; Services remains cryptographic verifier. Old-scope credentials never refresh-elevate.

GAP-04 · Restart replay

Recover without a new public resume grammar

Situation
Journals are named by operation UUID while approved commands have no --resume option.
Complication
A restarted command needs a deterministic lookup and ambiguity behavior.
Question
How is the prior operation found?

Recommended answer: for non-secret mutations, canonicalize validated intent, scan the bounded journal directory for one exact profile + command + fingerprint match, and resume its stored request ID/bytes. Zero matches create; multiple matches refuse OPERATION_RESUME_AMBIGUOUS. Do not add a public flag in 1.4.2.

GAP-05 · Secret replay

No dictionary-testable fingerprint

Situation
Secret input is request-only and may have low entropy.
Complication
A plain SHA-256 request fingerprint can be tested offline; stored bytes violate the no-secret-state rule.
Question
Can secret mutation cold-resume?

Recommended answer: exclude secret bytes and secret commands from cold-process replay in 1.4.2. Preserve identical in-memory bytes and request ID only across the one auth refresh/retry. A possible-effect timeout is indeterminate and stores no secret-derived fingerprint. Re-entry is an explicit new set operation.

GAP-06 · Route completeness

Freeze all client-visible semantics

Situation
Organization use, deploy completion, run polling and retirement preconditions remain underspecified.
Complication
Commands cannot be strict if they infer missing server behavior.
Question
Which exact routes and fields close the grammar?

Recommended answer: artifact must include organization detail/visibility, deploy creation receipt, bounded run polling (no streaming/ACP), revisioned retirement, a closed registration environment enum, and one request/idempotency header contract. worker status is remote authority only; settled local governance remains on existing local inspection surfaces.

GAP-07 · npm authority

Candidate publisher cannot move latest

Situation
Current trusted-publisher controls authorize npm publish only.
Complication
npm dist-tag add and reversal need different authority.
Question
How is the protected transition authenticated?

Recommended answer: create a separately protected promotion environment with the minimum approved npm authority, explicit approval and prior-tag readback. Never insert a broad maintainer token into the candidate workflow. Block Task 17 promotion until the mechanism is recorded.

GAP-08 · Staging identities

Worker consumes, never invents, live fixtures

Situation
Three-OS source and keychain checks are Worker-owned.
Complication
Two-human/two-organization staging needs I336 identities, endpoints and a redacted receipt sink.
Question
Who provisions and attests those fixtures?

Recommended answer: I336 supplies a signed staging manifest and scoped identities through its secret authority. Worker workflows consume exact profile and manifest digests. Block T16 live qualification; hermetic fixture-first and package work continues.

04

Testing strategy and TDD contract

Every production behavior begins with one focused red case; aggregate gates never substitute for the red proof.

Unit ownership

Pure boundary logic

Profile parsing, claims, schema compilation, route substitution, selectors, journal state, output and error classification use deterministic fakes.

Command ownership

Intent → one typed operation

Command tests use injected management clients and filesystem roots; they assert grammar, no side effects on help/refusal, and one result model.

Hosted ownership

Real authority and custody

GitHub Actions and I336 staging own real OS keychains, public origins, consent, demotion, response loss, registry bytes and hard-cut negatives.

Ordered RED → GREEN → REFACTOR rule

RED · one behaviorAdd the named test, run only its file, and record the expected failure caused by missing behavior—not syntax or fixture absence.
GREEN · minimum codeImplement the narrow public behavior; rerun the file and its nearest existing regression suite.
REFACTOR · preserve evidenceRemove duplication, run typecheck, then run the task gate. Do not advance with unrelated failures or skipped required cases.
